# 数据可用性与边界

这个项目模拟的是「巨量千川投放 + 商家经营」的数据层。目标不是把数据堆得很全，而是明确：

> **Agent 实际能拿到什么、拿不到什么、缺失时应该怎么表现。**

## 1. 数据源划分

| 层 | 数据 | 来源 | 可用性 / 限制 |
| --- | --- | --- | --- |
| 投放报表 | 消耗、展示、点击、支付金额、成交订单数、支付 ROI、订单成本 | 千川报表 | 账户 / 计划 / 日粒度；约 5 分钟刷新 |
| 投放报表 | 净成交金额、净成交订单、1 小时退款率、净成交 ROI | 千川报表 + 商品/交易授权 | 未授权账户为 `null`，不能当 0 |
| 账户 | 总余额、有效余额、共享钱包余额、授权状态 | 千川账户 / 资金接口 | 有效余额、共享钱包可能因权限缺失 |
| 计划 | 状态、预算、出价、出价策略、ROI 目标、投放时段、人群、学习期、审核原因 | 千川计划接口 | 计划配置可用；学习期 / 审核状态有延迟 |
| 素材 | 素材标题、类型、审核状态、拒绝原因 | 千川创意接口 | 部分账户有素材授权 |
| 商品 | 商品名、价格、库存、上下架状态 | 抖店 / 商品接口 | 本 demo 用商品实体模拟；真实接入需要店铺授权 |
| 调整记录 | 时间、字段、before/after、操作人、原因 | 千川调整记录 | 用于归因时间锚点 |
| 经营成本 | 商品成本、毛利、物流、退货、税费 | 商家 ERP / 财务 | **千川不提供**；本项目不生成、不用于判断绝对盈亏 |
| 竞品 / 大盘 | 竞品消耗、行业 ROI、自然流量增量 | 外部 / 实验 | **不提供**；不要编造 |

参考官方文档：

- [千川数据报表：可用维度和指标](https://open.oceanengine.com/labels/12/docs/1823296280645708)
- [全域投放控成本计划建议支付 ROI 目标](https://open.oceanengine.com/skiff/api/doc/client/markdown/get/?doc_id=1851652691167244&language=CHINESE)

> 报表约 5 分钟刷新、净成交/退款口径等细节，可参考第三方对账说明：[青虎AI：千川多账户数据对账](https://news.iqinghu.com/21445.html#1)。这是外部资料，不是官方承诺。

## 2. 缺失不是 0

Agent 最容易犯的错，是把“没拿到”当成“等于 0”。

本项目用 `DataHealth` 显式表达：

```ts
interface DataHealth {
  accountId: string;
  completeness: number;
  authorization: "已授权" | "部分授权" | "未授权";
  lastSyncedAt: string;
  lagMinutes: number;
  missing: string[];
  stale: string[];
}
```

前端在「数据健康」里展示：

- 最近同步时间、最大延迟
- 完整度
- 缺失字段（净成交 / 退款、完整授权）
- 哪些账户延迟、哪些账户部分授权

Agent 上下文会带上同样的信息，并明确：

- 缺失字段不能推断为 0；
- 缺失净成交时，只能用支付 ROI 做相对判断；
- 不能据此判断绝对盈亏。

## 3. 净成交与退款

真实千川报表同时存在：

- 支付金额 / 支付 ROI
- 净成交金额 / 净成交 ROI
- 1 小时退款率、净成交结算率

本项目的处理：

- `DailyPoint` 增加可选 `netRevenue`、`netOrders`、`refundAmount`、`refundRate`；
- 只有账户具备「商品交易」数据源时才生成；
- 否则为 `null`，UI 显示 `--` / “未同步”；
- 净成交拆分只汇总已授权账户，未授权账户不进入该口径；
- 净成交数据与支付数据分开展示，不混用。

## 4. 对账与切片

计划的日序列会归一化到账户日序列：

- 同一账户下，计划逐日的消耗 / 支付 / 订单 / 展示 / 点击 / 净成交 / 退款，加总等于账户；
- 因此按投放方式、推广目标拆分时，合计与账户 KPI 一致；
- 如果数据不一致，应先在「数据健康」里排查，而不是让 Agent 直接下结论。

## 5. 不提供的字段

以下字段在真实千川里通常拿不到，或需要额外系统，本项目**不生成**：

- 商品成本、毛利率、物流费、税费
- 最终退货率 / 退款原因明细
- 竞品消耗、行业大盘 ROI
- 自然流量增量、广告增量 lift
- 用户 LTV / 复购价值（除非商家提供）

所以 Agent 只能回答：

> 哪个切片 ROI 更高、订单成本更低、净成交更好、数据是否足够；
>
> 不能回答：
>
> “哪个切片一定在赚钱。”

## 6. 当前 mock 的取舍

- 数据是确定性生成的，便于复现和演示；
- 账户授权、数据源、同步时间、缺失字段都是模拟的；
- 计划配置（出价策略、ROI 目标、时段、人群、学习期、审核原因）按真实计划结构建模；
- 素材与调整记录只保留 Agent 做归因所需的字段；
- 成本/毛利明确不建模，避免用假数据得出“盈利/亏损”结论。
