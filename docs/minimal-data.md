# 最小数据可行性

目标：让 mock 数据刚好支撑 Agent 的「诊断 → 建议 → 执行 → 验证」，不为了展示而堆字段。

## 1. 最小实体与字段

| 实体 | 必填字段 | 用途 |
| --- | --- | --- |
| Account | `id`、`name`、`orgId`、`channel`、`status`、`budget`、`balance`、`authorization`、`lastSyncedAt` | 账户范围、预算/余额校验、数据可用性 |
| Product | `id`、`accountId`、`name`、`price`、`status`、`stock` | 商品上下文、售罄/下架约束 |
| Campaign | `id`、`name`、`accountId`、`productId`、`mode`、`target`、`status`、`budget`、`bid`、`learningPhase`、`rejectReason`、`roiGoal`、`updatedAt` | 计划诊断、暂停/预算/出价动作、学习期与审核约束 |
| DailyPoint | `date`、`cost`、`show`、`click`、`orders`、`revenue`，可选 `netRevenue`、`refundRate` | 趋势、ROI、订单成本、净成交 |
| DataHealth | `authorization`、`hasNetData`、`lastSyncedAt`、`lagMinutes` | 缺失/延迟门禁 |
| Operation | 现有字段 | 执行、回滚、审计 |
| Run | 现有字段 | 证据、审批、验证 |

## 2. 明确不进入决策的字段

这些字段可以留在详情页做展示，但不进入 Agent 上下文/决策：

- 人群：性别、年龄、地域、兴趣
- 素材：素材类型、素材审核原因、素材明细
- 排期：投放时段、时段类型
- 出价策略、落地页、直播间 ID/标题
- 账户有效余额、共享钱包余额
- 完整变更日志（只保留 `updatedAt` 用于冷却）

理由：它们对「暂停/改预算/改出价」不是必要条件，字段越多，模型误用和口径冲突的概率越高。

## 3. 动作所需的最小数据

| 动作 | 必需 | 缺失时 |
| --- | --- | --- |
| 暂停计划 | 计划状态、消耗、最近变更 | 可执行，低风险 |
| 改预算 | 余额、预算、消耗、ROI 趋势、最近变更、冷却期 | 数据过期/余额缺失 → 阻断 |
| 改出价 | 转化数、学习期、出价、ROI | 学习期/转化不足 → 阻断 |
| 放量 | 连续 N 天 ROI、净成交覆盖、库存 | 净成交缺失 → 只能相对建议，不能承诺收益 |

## 4. Agent 上下文只放这些

- 当前切片 KPI
- 投放方式拆分 / 推广目标拆分
- 净成交/退款（仅授权账户）
- 数据健康：完整度、延迟、缺失字段、部分授权
- 组织概览、Top 账户
- 当前操作/审批状态
- 商品助手额外放：近 7 天 ROI 走势；每条计划的素材汇总（条数 / 通过 / 拒绝 + Top 素材的消耗 / ROI / CTR / CVR / 5s 完播 / 退款率）；未来 7 天预测区间与建议动作

**不放**：完整素材明细、人群定向细节、排期、有效余额、共享钱包、完整变更日志。

## 5. 当前项目如何落地

- 当前 mock 的详情页仍保留部分可选字段，用于展示“真实工作台会有哪些信息”；
- Agent 上下文只取上表核心字段；
- `dataHealthOf` 只检查决策关键项：净成交/退款、授权、延迟；
- 智能助手再缩一层：只取「该商品 → 该账户 → 该商品的 1–N 条计划」，不把其他商品放进上下文；
- 如果后续继续收敛，优先删除详情页里不影响动作的字段/面板，而不是继续加字段。
