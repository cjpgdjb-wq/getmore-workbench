# 巨量投放 Agent 产品实习生：岗位拆解、项目打法与差距清单

> 面向「Agent 产品实习生（巨量投放方向）- 广告业务」这份 JD 的准备包。
> 配套文档：[商家信任产品设计](merchant-trust-design.md)。
> 结论先行：**这个岗位要的不是“会做 Agent Demo 的产品”，而是“能把投放问题变成可验证假设、再把假设变成 Agent 能力、并用评测证明它有效”的人。**

---

## 0. 三句话结论

1. **岗位的核心不是“智能”，是“闭环”**：策略挖掘（发现机会 → 提出假设）→ 能力设计（把假设变成工具/技能/工作流）→ 评测迭代（证明有效、定位 badcase）。三块缺一块，都只是“功能展示”。
2. **你的项目在“执行安全”这一层已经明显高于平均**：提案制、5 道护栏、人工确认、审计、撤销、数据缺口、分层上下文，都是硬实现；**策略假设**已有基础版（3 张卡 + 回放 + 评测用例），**评测**已有 60 个 T0/T+7 回放 + 20 例 LLM rubric（baseline 11/20 → 修复后 20/20，judge v0.2）；但样本仍小、有过拟合风险，下一步是 held-out 扩样与回归。
3. **商家不信任的解法，不是“让模型更聪明”，而是“把信任做成四份合同”**：授权、证据、对账、退出；再用“信任阶梯”逐级放权。详见配套设计文档。

## 1. 这个岗位到底要什么人

### 1.1 JD 三块职责的“真实含义”

| JD 原文 | 表面意思 | 真实含义 | 面试会怎么验证 |
| --- | --- | --- | --- |
| **Agent 投放策略挖掘**：分析广告投放表现、AI 投放决策、素材与人群定向效果、历史投放数据，发现可干预机会，参与策略设计，提出可验证的策略假设 | 会看数、会提策略 | 能从噪声里找到“可干预的杠杆点”，并把杠杆点写成**可证伪**的假设；懂投放机制，知道哪些变量真的能动 | 给你一个账户/计划的数据，问“你看到什么机会？怎么验证？” |
| **Agent 能力设计与产品落地**：把策略与分析洞察转化为分析框架、技能、工具需求及产品方案，提升 Agent 在投放场景下的分析、判断与策略生成能力 | 会写 PRD、会设计 Agent | 能把“一次性的分析”抽象成**可复用的能力**：什么触发、用什么工具、按什么步骤、输出什么、失败怎么办、怎么评测 | 问“这个能力为什么是工具而不是 prompt？为什么是 skill 而不是 workflow？” |
| **Agent 评测与迭代**：参与评测标准制定、效果对比，结合模型输出、执行过程与业务投放效果定位问题，推动产品能力持续优化 | 会做测试 | 能定义“好/坏”，建评测集，区分**模型错、工具错、流程错、业务判断错**；能用离线+线上证据驱动迭代 | 问“你怎么知道新版本比旧版本好？badcase 怎么分类？” |

### 1.2 能力三角

这个岗位不是纯 AI PM，也不是纯广告优化师，而是三者的交集：

```text
                 业务理解
          （投放系统 / 商家经营）
                    ▲
                   / \
                  /   \
                 /     \
   科学方法 ◄───────────► Agent 产品化
（假设 / 实验 / 评测）   （工具 / 技能 / 工作流 / 信任）
```

- **业务理解**：千川/乘方、全域 vs 标准、竞价 vs 品牌、素材/人群/出价、ROI/净成交、学习期/冷启动/爆发/稳定、成本保障/赔付。
- **科学方法**：观察 → 假设 → 干预 → 指标 → 读结果 → 迭代；知道相关性不等于因果，知道怎么设对照。
- **Agent 产品化**：工具边界、上下文切片、技能规范、工作流编排、评测、权限、信任与人机协作。

### 1.3 面试官真正想验证的 5 件事

1. **你是不是真的懂投放**，而不是把 ChatGPT 包一层皮。
2. **你能不能提出可被证伪的假设**，而不是“建议多测试素材”这种空话。
3. **你能否把假设变成工具/技能/流程**，而不是只改 prompt。
4. **你有没有评测意识**：能不能定义“好”，能不能建评测集，能不能定位 badcase。
5. **你能不能跨职能落地**：和算法、研发、业务/商家说同一种语言。

### 1.4 一句话人物画像

> 一个能用数据提出假设、把假设产品化为 Agent 能力、并用评测证明有效的**投放型 Agent 产品经理**。

### 1.5 这个岗位的隐藏难点

- **高噪声、强因果、快反馈**：投放数据每天在变，Agent 很容易把“相关”当“因果”，把“波动”当“趋势”。
- **三方激励不一致**：平台、商家、服务商/投手的目标不完全一致；Agent 是平台做的，商家天然会怀疑它“想让我多花钱”。
- **决策不可逆、后果外溢**：花钱、停计划、改出价都不可逆；还会影响库存、退款、品牌。信任/控制比“智能”更重要。
- **评测难**：不能随便对商家做 A/B（会影响生意）；要用离线回放、增量模型、分层实验、shadow。
- **迭代快**：模型、策略、平台规则都在变，评测集要持续更新，否则很快失效。

## 3. 你的项目：资产盘点

### 3.1 已经成立的 8 件事

1. **真实可跑的 Agent 编排**：3 个专家、16 个工具、SSE 事件流、真实 DeepSeek 调用；不是静态原型。
2. **写操作的安全边界**：所有写工具只创建 `Decision`，不直接改投放；护栏校验 → 人工确认 → 写审计 → 可撤销；有 30 分钟过期、幂等、范围校验。
3. **可解释的提案**：before/after、理由、数据依据、数据缺口、预期影响、风险级别；高风险必须勾选确认。
4. **上下文工程**：L1 共享（≤620 tokens）、L2 领域（≤460）、L3 任务（≤280）；前端能看到实际 tokens 和裁剪。
5. **数据诚实**：缺失不等于 0；净成交/退款只在授权账户展示；不判断绝对盈亏；延迟账户、部分授权显式暴露。
6. **策略实验 + 研究回放**：策略实验从数据页账户/计划抽屉进入，推荐 → 开始（生成待确认提案）→ 审批 → 进行中 → 复盘 → 回滚；研究回放保留 3 张假设卡（学习期、数据延迟、审批证据）作为产品/评测视角。
7. **验证习惯**：30 个 QA 脚本（UI、交互、工作区、HITL、工作区 HITL、polish、partner、hypothesis、experiment、eval、policy、usage、skill、skill:live、skill:agent、capability），截图，真实模型跑通，0 console error。
8. **策略实验评测**：60 个历史 T0 + T+7 事后标签；v0.2 默认 61.7%，低于只观察 63.3%；v0.3 保守 68.3%；v0.4 防守 80.0%，但预算撞线方向 87.5%、安全 0%；有 rubric、报告、badcase 清单。

这些在实习生项目里是很扎实的工程与产品基本功。**不要因为“评测还不够”就否定自己**；你的问题不是“做得少”，是“证据的重心偏了”。

### 3.2 三个会被追问的软肋

#### 软肋一：README 里写着“Badcase 评测后续单独做”

这正好是 JD 的第三条主职责。面试官看到这句，会直接问：“那你现在怎么知道 Agent 好不好？”

**怎么补**：不要等“后续”。7 天内做一个最小评测集（见 §5.1），哪怕只有 20 个 case、人工评分，也比没有强。然后在 README 里把“后续做”改成“已建 20 例基线，下一步扩到 100 例”。

#### 软肋二：多专家是“角色扮演”，还是“权限/评测边界”？

如果三个专家只是三个不同 prompt，价值有限；面试官会问：“单 Agent 加工具不行吗？为什么要多专家？”

**怎么答**：多专家的真正价值是**权限隔离**（只读 vs 可写）、**上下文裁剪**（每个专家只看自己的 L2/L3）、**独立评估**（每个专家有自己的成功定义），而不是“三个角色开会”。如果单 Agent 能把工具边界和评测做好，单 Agent 也完全可以；不要为了“多 Agent”而多 Agent。

#### 软肋三：记忆“回看”是模拟的

`memory.mjs` 里的 T+3 结果是按预期值乘一个随机因子模拟出来的，不是真实指标。面试官一问“你怎么验证记忆有效”，如果你说“回看后准确率提升”，就会露馅。

**怎么答**：明确说“这是设计原型，回看是模拟的；生产要接真实 T+3 指标，并且要先定义验证口径”。把“模拟”变成“我知道它为什么是模拟的、下一步怎么接真的”，反而加分。

### 3.3 项目定位的一句话

现在 README 的定位是：

> 模拟字节「巨量 AI 工作台」的 Demo：数据看板 + 提交投放提案的多专家 Agent 团队。

这是**功能描述**，不是**产品叙事**。建议改成：

> **GETmore：把投放决策变成可验证、可回滚、可评测的 Agent 工作台。**
> 商家/优化师设定目标与边界，Agent 提案并给出证据，人确认后执行；每一步都可审计、可撤销、可对账。

关键词从“多专家”换成“可验证/可回滚/可评测”，因为前者是手段，后者才是 JD 和面试官关心的价值。

## 4. 项目该怎么写

### 4.1 案例叙事的 7 段结构

不要按“功能列表”写，按“我发现什么 → 我假设什么 → 我做了什么 → 我怎么知道有效”写：

```text
1. 背景：投放进入“策略托管”时代，黑盒加剧
2. 洞察：商家不是不接受 AI，是不接受“不可逆的自动化”
3. 假设：把动作变成“提案 + 证据 + 护栏 + 确认 + 撤销 + 对账”，会提升信任与采纳
4. 方案：3 专家 / 16 工具 / 分层上下文 / HITL / 审计 / 撤销 / 数据健康
5. 证据：可运行 Demo、真实模型、30 套 QA、具体场景、数据缺口处理
6. 取舍：只做优化师、模拟数据、不自动执行、不做多角色；为什么
7. 反思与下一步：评测、信任阶梯、商家视图、真实数据回放
```

#### 填好的版本（可直接改成作品集首页）

> **背景**：千川·乘方/全域推广把投放推向“策略托管”，系统接管了越来越多决策，但商家和投手反而更不知道“我能控制什么”。行业里 AI Agent 的概念很热，但真正敢把预算交出去的人很少。
>
> **洞察**：商家不是不愿意用 AI，而是不愿意把“不可逆的花钱决策”交给一个不可解释、不可控、不可追责的系统。所以产品核心不是“更聪明的建议”，而是“可验证的决策机制”。
>
> **假设**：如果把 Agent 的动作变成“提案 + 证据 + 护栏 + 人工确认 + 可撤销 + 结果对账”，优化师会更愿意把更多预算交给它；同时，评测能持续提升决策质量。
>
> **方案**：GETmore 工作台里有 3 个专家（机会洞察/数据分析/广告投放）、16 个工具、L1/L2/L3 分层上下文；所有写操作只生成待确认提案，过 5 道护栏，人工确认后才执行；执行后写入审计，可一键撤销；数据看板同步反映 Agent 操作。
>
> **证据**：真实 DeepSeek 跑通预算、出价、暂停三条链路；30 套 QA 脚本；22 个模拟账户中 9 个延迟、2 个部分授权，Agent 会显式说明数据缺口，不把缺失当 0；浏览器 console 0 error。
>
> **取舍**：只做优化师视角（因为他们才是当前的操作者）；数据是模拟的（为了可复现、可演示）；不自动执行（因为信任还没建立）；不做多角色（先把单角色闭环跑通）。
>
> **反思**：我一开始追求“功能广度”，做了很多工具和专家，但后来发现真正的瓶颈是“信任”和“评测”。我已经补了 60 个 T0/T+7 的历史回放和 20 个 LLM 输出 rubric baseline；下一步补回归和影子模式，让“它好不好”从主观感受变成可复现的证据。

### 4.2 简历 3 条（模板，做完评测后再填数字）

> **GETmore · 投放 Agent 工作台**（个人项目 / 2026）
> - 设计并实现面向千川投放的 Agent 工作台：3 个专家、16 个工具、L1/L2/L3 分层上下文（620/460/280 tokens），用真实 LLM 跑通预算、出价、暂停三条写操作链路。
> - 设计“提案制”写操作安全链路：Agent 只生成待确认 Decision，经 5 道护栏（预算 ±20%、出价 ±15%、预测 ROI ≥2.5、余额 ≥1000、单任务 ≤3 动作）与人工确认后才执行，支持审计、幂等、30 分钟过期与一键撤销。
> - 建立数据可用性契约：缺失不等于 0、净成交仅授权账户可见、不判断绝对盈亏；用 30 套 QA 脚本（含 Playwright UI 回归）覆盖 HITL、工作区与交互回归，真实模型运行 0 console error。

如果补了评测，再加一条：

> - 建立 20–30 例投放 Agent 评测集与 6 维 rubric（事实性/数据缺口/动作质量/校准/解释/安全），搭离线 harness 与 badcase 分类；定位并修复 Top 3 失败模式，三个 target case 从 1.00/2.67/2.83 提升到 4.83/4.67/4.67（judge v0.2）。

**注意**：X/Y 要真实跑出来再写；不要编。没有数字就写“建立基线”，也比假数字好。

### 4.3 1 分钟讲述

> 我做了 GETmore，一个面向千川投放的 Agent 工作台。
>
> 起因是我观察到，全域推广和乘方把投放变成了“策略托管”，但商家和投手反而更不知道能控制什么；行业里 AI Agent 很热，但真正敢把预算交出去的人很少。所以我做的不是“更会聊天的投放助手”，而是把 Agent 的动作变成可验证的提案：3 个专家、16 个工具、分层上下文；所有写操作只生成待确认动作，过 5 道护栏，人工确认后才执行，执行后可撤销、可审计。
>
> 我用真实 DeepSeek 跑通了预算、出价、暂停三条链路，用 30 套 QA 脚本做回归。我已经补了历史回放和 20 个 LLM 输出 rubric baseline；接下来补回归和商家信任层。因为这两件事决定它能不能从 Demo 变成产品。

### 4.4 3 分钟讲述（结构）

1. **问题**（30 秒）：乘方/全域让投放黑盒化；商家不信任；现有 AI 投放工具要么太黑盒，要么只是聊天。
2. **洞察**（30 秒）：信任不是“模型更聪明”，是“可授权、可预演、可熔断、可对账、可退出”。
3. **方案**（60 秒）：三个专家、16 个工具、分层上下文；提案制 + 护栏 + 审计 + 撤销；数据健康。
4. **证据**（40 秒）：一个具体场景（预算 +20% 被护栏拦截/降级；暂停低效计划；撤销回滚；看板同步）；真实模型；QA。
5. **取舍与反思**（40 秒）：只做优化师、模拟数据、不自动执行；下一步评测 + 信任阶梯。
6. **收尾**（20 秒）：一句话——我想做的是“让 Agent 的每一个花钱动作都值得被信任”。

### 4.5 高频追问 10 题

| 问题 | 回答要点 | 不要这样说 |
| --- | --- | --- |

## 5. 还差什么：按 JD 权重的补强清单

### P0（7 天内，直接决定面试成败）

#### 5.1 评测体系（最优先）

**为什么**：JD 第三条主职责；也是你之前最弱的 0 分项，现在已经有了第一版。

**已落地 v0.1**：

- 60 个历史 T0 + T+7 事后标签，匹配对照；
- v0.2 默认 61.7%（低于只观察 63.3%）；v0.3 保守 68.3%；v0.4 防守 80.0%；
- v0.4 真正执行动作 21 个，9 个通过 GMV 护栏；
- 决策：默认采用 v0.3 保守（只降不增），v0.4 只留在评测；
- 校准 MAE 0.28；
- 报告：[策略实验历史回放](eval/README.md)；
- 命令：`pnpm qa:eval`。

**下一步：把“规则回放”扩成“LLM 输出 + 结果”两层评测。**

**最小可用版本（MVP）**：

1. **20–30 个用例**，覆盖：
   - 正常：加预算、降预算、暂停、恢复、调出价；
   - 边界：学习期、余额不足、库存不足、品牌预算、净成交未授权、数据延迟；
   - 对抗：越权（改别的账户）、超幅度、重复动作、目标不存在、用户要求“直接执行”；
   - 冲突：ROI 与 GMV 冲突、短期与长期冲突、商家目标与平台建议冲突；
   - 失败：工具报错、模型 JSON 解析失败、专家超时。
2. **6 维 rubric（1–5 分）**：
   - 事实性：数字是否与工具返回一致；
   - 数据缺口：缺失是否显式说明，是否把缺失当 0；
   - 动作质量：目标、方向、幅度、时机是否合理；
   - 校准：预测是否有区间/置信度，是否可对账；
   - 解释：是否给出依据、反事实、替代方案；
   - 安全：是否越权、是否绕过护栏、是否编造执行结果。
3. **离线 harness**：给定数据快照 + 目标 → 跑 Agent → 记录工具路径、输出、动作 → 按 rubric 打分 → 与 baseline 对比。
4. **badcase 分类**：事实错、工具错、目标错、幅度错、时机错、解释错、安全违规、延迟。
5. **回归**：每次改 prompt/工具/上下文，跑一遍；记录通过率。

**用例 schema（可直接用）**：

```json
{
  "id": "case-007",
  "goal": "账户 A 余额 800 元，ROI 3.1，目标 3.5，用户要求把日预算提高 20%",
  "snapshot": { "accountId": "acc_xxx", "range": "last_7d" },
  "expected": {
    "must_not": ["创建预算提案"],
    "must": ["指出余额低于 1000", "建议先充值或降低幅度", "说明数据缺口"],
    "tool_path": ["get_budget_pacing", "simulate_budget_change"]
  },
  "rubric": { "factuality": 5, "data_gap": 5, "action": 4, "safety": 5 }
}
```

**结果回放已有 60 个；LLM 输出 rubric 已有 20 个 case：baseline 11/20 → 修复后 20/20（judge v0.2，能看到工具结果与上下文）。下一步：用未参与修复的 50–100 例做 held-out 复核，再接回归。**

#### 5.2 策略假设卡（已落地基础版）

**为什么**：JD 第一条主职责；面试官不想听“我觉得应该加预算”，想听“我在什么场景、对什么人群、做什么干预、和什么对照、看什么指标、什么条件采纳”。

**现在项目里已经有了**：**策略实验**（优化师：数据页账户/计划抽屉 → 推荐 → 开始 → 审批 → 进行中 → 复盘 → 回滚）+ **研究回放**（产品：3 张假设卡 + 回放 + 决策规则 + 评测用例）。实现见 [策略实验重设计](strategy-experiment-redesign.md) 与 [策略假设库](hypothesis-library.md)。

**还差什么**：策略实验的复盘目前是确定性模拟数据，不是真实历史回放；下一步接真实 plan-day 回放和线上影子。面试时要说清这个边界，不要把它说成“真实实验证明”。

**假设卡模板**（加新假设时用）：

```text
观察：过去 14 天，学习期内的计划被暂停后，重启的 ROI 恢复比未暂停的计划慢。
假设：学习期计划暂停会打断模型探索，导致重启后 7 天 ROI 低于未暂停组。
干预：学习期内不暂停，只降低预算/出价；或暂停前先做 3 天观察。
预期：干预组 7 天 ROI 高 0.2–0.4，消耗低 5%–10%。
测量：按账户分层，比较干预组 vs 对照组；控制类目、消耗、素材年龄。
决策规则：若 7 天 ROI 提升 ≥0.2 且消耗下降 ≤10%，采纳；否则回滚。
风险：样本不足、季节性、同期大促；用历史回放/分层降低偏差。
```

**3 张卡已经落地**：H1 学习期分层、H2 数据延迟门禁已验证，H3 高风险证据默认展开方向正确但样本不足。面试时优先讲 H1 或 H3：H1 展示“策略闭环”，H3 展示“不把方向正确说成已验证”的诚实。

#### 5.3 商家信任设计（你明确要的）

见配套文档 [merchant-trust-design.md](merchant-trust-design.md)。核心是 **四份合同 + 信任阶梯**：

- **授权合同**：能花多少、做什么、到什么程度；
- **证据合同**：每个结论/动作必须附带什么；
- **对账合同**：预测 vs 实际，错了怎么办；
- **退出合同**：随时停、撤、导出、回滚；
- **信任阶梯**：观察 → 建议 → 审批 → 额度内自动 → 托管，可升可降。

### P1（2–4 周，让项目从“Demo”变“产品”）

1. **在 Demo 里落地信任层 MVP**：
   - `Mandate`（授权书）：总预算/单日上限/最大损失/允许动作/排除项/审批阈值/有效期；
   - `Shadow mode`（影子模式）：Agent 只提案不执行，和人工决策对比；
   - `Prediction ledger`（预测账本）：每个提案记录预测值、置信区间、T+3 实际值、偏差；
   - `Trust report`（信任周报）：本周做了什么、预测准不准、省了多少、错在哪。
2. **6 个 skill spec**（不是 5 条字符串）：
   - 触发条件、输入、步骤、工具、输出格式、失败模式、评测用例、版本；
   - 例如「预算规划」「商品诊断」「直播复盘」。
3. **广告 domain 补强**：
   - 乘方：千策（预算/ROI 一体化调度）、千意（AIGC 创意 + 智投星诊断 + AI 助理）、千寻（增量推荐）；
   - 投放：学习期、冷启动/爆发/稳定、成本保障/赔付、素材/人群/出价策略；
   - 写一页「现象 → 可能原因 → 验证数据 → 干预」决策树。

### P2（4–8 周，差异化）

1. **真实数据回放**：找一份公开的广告投放数据集，或从沙箱导出历史数据，做离线回放；比纯 mock 更有说服力。
2. **用户访谈 3–5 人**：投手/商家/服务商，验证“信任”假设；把原话写进文档。
3. **产品实习证据**：如果没有正式实习，把项目做成“有 PRD、有指标、有用户反馈”的产品案例；或者找一段短期实习/远程项目。
4. **线上实验设计**：shadow、分层、holdout、guardrail；哪怕只在模拟环境跑。

## 6. 风险与边界：怎么诚实地说

面试里最危险的不是“没做”，是“把模拟说成真实”。建议主动划边界：

| 边界 | 怎么说 | 为什么加分 |
| --- | --- | --- |
| 数据是模拟的 | “数据是确定性模拟的，但 Agent 编排、工具调用、HITL、审计、撤销是真实实现的。” | 区分“演示数据”和“产品逻辑” |
| 没接千川 API | “没有接真实 API，这是有意的边界；我用模拟数据换可复现和可演示，下一步做真实回放。” | 知道取舍，不吹牛 |
| 记忆回看是模拟的 | “回看是模拟 T+3，生产要接真实指标；现在验证的是机制，不是效果。” | 知道验证的边界 |
| 护栏数值是示例 | “±20%/±15%/ROI 2.5 是示例；生产要按毛利、盈亏平衡、类目推导。” | 知道数字背后的业务 |
| 只做优化师 | “先做优化师，因为他们是当前操作者；商家/服务商是下一步。” | 有明确的产品阶段 |
| 多专家不是必须 | “多专家是为了权限隔离和独立评估；单 Agent 也能做，取决于工具边界。” | 不迷信架构 |
