# 策略假设怎么做：从数据到实验，再到 Agent 能力

> 面向「巨量投放 Agent」的策略假设工作法。
> 配套：[岗位拆解与项目打法](agent-pm-fit.md)、[商家信任产品设计](merchant-trust-design.md)。
> 项目里已经落地 3 张假设卡 + 回放 + API/UI，见 [策略假设库](hypothesis-library.md)。

---

## 0. 一句话

**策略假设不是“我觉得应该加预算”，而是一个可被证伪的因果陈述：**

> 在【什么人群/场景】下，做【什么干预】，相对于【什么对照】，在【多长时间】内，【主指标】会【方向 + 幅度】，且【护栏指标】不破【底线】；如果【验证结果】，就【采纳/迭代/放弃】。机制是【为什么】。

没有对照，就不是假设，是愿望；没有机制，就是碰运气；没有决策规则，就是做完再说。

## 1. 先分清五个东西

很多人从“观察”直接跳到“动作”，中间缺了三层。策略假设是中间那层。

| 层 | 定义 | 例子 |
| --- | --- | --- |
| **观察** | 数据里看到的现象 | 18 个学习期计划，7 天消耗 27.6 万；ROI 从 2.41 到 5.25 不等 |
| **洞察** | 对现象的解释 | 学习期不是“低效期”，而是“高异质期”；一刀切暂停会误伤高效计划 |
| **假设** | 可证伪的因果陈述 | 按“ROI 趋势 + 转化量 + 消耗规模”分层干预，比统一暂停能提升 7 天 ROI，且 GMV 不降 |
| **策略** | 可执行的决策规则 | ROI <3.0 且转化 <20/天 → 降预算 10%；ROI ≥3.5 且趋势向上 → 加预算 5%；其余观察 |
| **动作** | 具体的工具调用 | `apply_budget_change` / `adjust_bid` / `pause_plan` |

> 面试里，如果你能从“观察”讲到“假设”再讲到“实验”，你已经超过大多数候选人；如果直接讲“我做了个功能”，你就只是功能经理。

## 2. 一个好假设的 7 个要素

### 2.1 模板

```text
在【人群/场景】下，
如果做【干预】，
相对于【对照/现状】，
在【时间窗】内，
【主指标】会【方向 + 幅度】，
且【护栏指标】不破【底线】。
如果【验证结果】，则【采纳/迭代/放弃】。
机制是【为什么】。
```

### 2.2 七个要素

| 要素 | 要写清楚 | 反例 |
| --- | --- | --- |
| **人群/触发** | 谁、什么条件下 | “所有账户” |
| **干预** | 具体做什么、做多少、做多久 | “优化一下预算” |
| **对照** | 和谁比：不行动 / 现状 / 其他策略 | “看效果” |
| **主指标** | 一个主指标 + 方向 + 幅度 | “提升 ROI” |
| **护栏** | 不能破的底线 | 没有护栏 |
| **时间窗** | T+1 / T+3 / T+7；观察多久 | “长期” |
| **决策规则** | 什么结果采纳、什么结果放弃 | 做完再说 |

### 2.3 自检 6 问

1. 如果结果相反，我会改变做法吗？——不会，就不是假设。
2. 对照是谁？——没有对照，就无法归因。
3. 机制是什么？——说不出“为什么”，大概率是噪声。
4. 数据和样本够吗？——不够就先回放/影子，别硬做 A/B。
5. 最坏情况多大？——护栏和止损先写。
6. 决策规则预先写了吗？——没写，就会“事后合理化”。

## 3. 假设从哪里来：7 个透镜

| 透镜 | 要问的问题 | 看什么数据 | 例子 |
| --- | --- | --- | --- |
| **异常** | 哪里偏离了趋势/基准？ | 日序列、环比、残差 | 某账户 ROI 连续 3 天低于目标 |
| **分层** | 效果集中在哪一层？ | 投放方式、推广目标、学习期、类目、账户规模 | 学习期计划内部 ROI 差异极大 |
| **漏斗** | 漏在哪一段？ | 展示→点击→转化→退款 | CTR 正常但 CVR 掉，可能是承接/价格 |
| **时间** | 什么时候发生变化？ | 变更日志、学习期、素材年龄、大促 | 素材第 5 天开始衰退 |
| **反事实** | 如果不做会怎样？ | 同类账户、历史回放、合成控制 | 暂停低效计划后，账户 ROI 是否真的回升 |
| **机制** | 为什么会这样？ | 竞价、预算节奏、探索、归因 | 预算撞线导致消耗忽高忽低 |
| **行为** | 人的操作如何影响结果？ | 审批、干预、撤销、反馈 | 投手在爆发期手动关素材，打断探索 |

Agent 产品还要加一个透镜：

| 透镜 | 要问的问题 | 例子 |
| --- | --- | --- |
| **Agent 失败** | 工具错、上下文缺、目标错、幅度错、时机错、解释错？ | 数据延迟时提案暂停，实际是数据没到 |

## 4. 用你的项目数据怎么找：5 个动作

### 4.1 按切片看 ROI / CPA / 消耗

按 `mode`（全域/标准）、`target`（推商品/推直播间）、`learningPhase`、`authorization`、`dataLagMinutes` 分组，算 7 天消耗、ROI、CPA、订单。

当前 mock 快照（34 个账户、65 个计划）里能看到：

- 18 个学习期计划，7 天消耗 **276,343 元**，ROI 区间 **2.41–5.25**；
- 其中 **11 个 ROI ≥3.0**（3 个 ≥4.0），**7 个 ROI <3.0**；
- 7 个低 ROI 学习期计划只花了 **41,441 元**，而 3 个高 ROI（≥4.0）学习期计划花了 **106,998 元**。

> 这就是一个很好的“观察”：**学习期不是低效期，是高异质期。** 一刀切暂停会误伤高效计划；一刀切放量会放大低效消耗。

### 4.2 看变化，不只看快照

- 当前 7 天 vs 上一 7 天：消耗、支付、ROI、CPA 的 delta；
- 用“贡献度”拆解：是哪个账户/计划/切片导致了大盘变化；
- 看拐点：哪一天开始变、当天有什么变更（`changes`）。

### 4.3 找“高消耗低 ROI”和“高 ROI 低消耗”

- 高消耗低 ROI：止损候选；
- 高 ROI 低消耗：放量候选；
- 但都要看库存、余额、学习期、数据健康，否则会做出“正确的错误动作”。

### 4.4 看数据健康

当前快照里有：

- 8 个账户数据延迟 16–21 分钟；
- 2 个竞价账户 + 1 个品牌账户部分授权；
- 部分账户净成交/退款不可见。

这些不是“背景信息”，而是**假设的边界条件**：数据延迟时，Agent 的“ROI 下滑”可能是假信号；部分授权时，支付 ROI 可能高估真实回报。

### 4.5 看 Agent 行为日志

你的 `.runtime/partner` 里有真实运行数据：

- 31 个 Decision：19 approved、7 rejected、2 expired、3 pending；
- 26 个 Operation：11 个被撤销（42%）；
- 109 次工具调用，1 次失败（`simulate_budget_change`）；
- 8 次运行，专家中位耗时约 16 秒，整轮约 32 秒。

**但先别急着下结论。** 看审批耗时：19 个 approved 的中位耗时是 **0.057 秒**，看起来像“橡皮图章”。再看法备注：`HITL regression`、`workspace HITL smoke`、`plan budget smoke`——这些是 QA 脚本，不是真人。

> 这是一个重要教训：**先问数据是谁产生的，再谈行为假设。** 如果我把 0.057 秒当成“审批疲劳”的证据，就是典型的“数据来源混淆”。

## 5. 三个完整案例

### 案例 A：学习期计划的分层干预（策略型假设）

#### 观察

18 个学习期计划，7 天消耗 27.6 万；ROI 2.41–5.25；11 个 ≥3.0，7 个 <3.0；低 ROI 组只花了 4.1 万，高 ROI 组花了 10.7 万。

#### 洞察

学习期计划不是“都该暂停”，也不是“都该放量”；真正的问题是**缺少分层规则**：低效的没止损，高效的没放量。

#### 假设

> 在学习期（3–14 天）竞价计划中，按“ROI 水平 + ROI 趋势 + 转化量 + 消耗规模”分层干预，相对于“统一暂停低 ROI 计划”，7 天后干预组 ROI 高 ≥0.2，GMV 不低于 -5%，低效消耗占比下降 ≥3pp。

#### 策略

| 分组 | 条件（示例） | 动作 |
| --- | --- | --- |
| A 止损 | ROI <3.0 且趋势向下/持平，转化 ≥20/天，7 天消耗 ≥5,000 | 预算 -10%，观察 3 天；不直接暂停 |
| B 放量 | ROI ≥3.5 且趋势向上，库存 ≥7 天，余额 ≥3 天 | 预算 +5%，单次不超过 10% |
| C 观察 | 其他（尤其转化 <20/天、数据延迟、部分授权） | 不动作，补数据/等窗口 |

#### 对照

- 现状对照：当前人工策略（低 ROI 就暂停）；
- 或匹配对照：同品类、同投放方式、同目标、同消耗层的计划；
- 或历史回放：同一批计划在上一个周期的表现。

#### 指标

- 主指标：7 天 ROI；
- 业务指标：GMV、订单、低效消耗占比；
- 护栏：消耗不超预算、ROI 不低于底线、库存/余额不破、数据完整；
- 过程指标：学习期退出率、重启成本、动作撤销率。

#### 测试

1. **离线回放**：用历史 plan-day 数据，比较 A/B/C 三组策略的事后表现；先做 2–4 周回放；
2. **影子模式**：Agent 只提案不执行，和人工决策对比 2 周；
3. **账户级分层实验**：如果样本足够，按类目/消耗层随机分组；否则用 stepped-wedge。

#### 决策规则

- 若 7 天 ROI 提升 ≥0.2、GMV 不低于 -5%、低效消耗占比下降 ≥3pp → 采纳；
- 若 ROI 提升但 GMV 下降 >10% → 迭代（只做止损，不做放量）；
- 若护栏破了 → 回滚，检查机制假设。

#### 风险

- 选择偏差：Agent 只挑“看起来能救”的计划；
- 回归均值：低 ROI 计划本来就会反弹；
- 干扰：预算变化影响竞价环境；
- 数据限制：mock 数据没有真实因果信号，只能验证方法和流程，不能验证效果。

#### 产品化

- 工具：`get_learning_state`（学习期/转化量/趋势）；
- 策略：分层规则 + 护栏 + 置信度；
- 技能：`learning_phase_policy`；
- 评测：正例/反例/边界（转化不足、数据延迟、库存不足、品牌计划）。

### 案例 B：数据延迟导致误停（Agent 型假设）

#### 观察

8 个账户数据延迟 16–21 分钟；Agent 在日初看到“ROI 下滑”时，可能基于不完整数据提案暂停。

#### 假设

> 对数据延迟 >15 分钟的账户，要求“连续 2 个完整数据窗口 + 数据完整度 ≥90%”才允许提交暂停提案，相对于当前“看到下滑就提案”，误停率下降 ≥30%，且漏损（该停没停）增加不超过 2%。

#### 干预

- 数据完整度门禁：`data_completeness >= 0.9`；
- 连续 2 个窗口确认；
- 延迟账户降级为“建议观察”，不自动执行；
- 提案里显式写“数据缺口”。

#### 对照

- 当前策略：单窗口 + 无门禁；
- 离线回放：历史 alert 中，哪些是假信号、哪些是真下滑；
- 影子：Agent 提案 vs 人工判断。

#### 指标

- 误停率（被暂停但本可恢复）；
- 漏损（该停没停造成的损失）；
- 提案通过率、撤销率、time-to-action；
- 数据缺口误用率。

#### 测试

- 用历史 alert + 事后 3 天数据做混淆矩阵；
- 若没有真实延迟数据，构造合成延迟（把某天数据截断）做回放；
- 影子 2 周，记录“如果执行了会怎样”。

#### 产品化

- 工具/门禁：`data_completeness_gate`；
- 策略：延迟账户只读/只建议；
- 评测：延迟、部分授权、数据缺口、假信号。

> 这个假设特别适合你的项目：你已经有 `DataHealth`、`Decision`、`Operation`，缺的是“事后结果”和“误停/漏损”的标注。

### 案例 C：审批疲劳（以及它为什么可能是个假信号）

#### 观察

31 个 Decision，19 个 approved；审批耗时中位数 0.057 秒；26 个 Operation 中 11 个被撤销（42%）。

#### 初步假设

> 审批太快 = 橡皮图章；商家/优化师没有看证据就点确认，导致错误动作被放行。

#### 先验证数据来源

看 `comment`：`HITL regression`、`workspace HITL smoke`、`plan budget smoke`——这些是 QA 脚本，不是真人。**所以这个假设在当前数据上不成立**；它测的是测试脚本，不是审批行为。

#### 修正后的假设

> 在中风险提案中，把“证据默认展开 + 一键对比反事实”作为默认交互，相对于“默认折叠 + 直接确认”，真人审批的证据查看率提升 ≥20pp，错误批准率下降 ≥10%，审批时长增加不超过 15 秒。

#### 测试

- 先在 Demo 里埋点：证据展开、停留时长、修改幅度、拒绝原因；
- 用种子 badcase（故意给错数据/错动作）测“人能不能发现”；
- 小样本 lab / 商家访谈，不要直接上生产 A/B。

#### 指标

- 证据查看率、橡皮图章率（<3 秒且未展开证据）；
- 错误批准率、撤销率、修改率；
- 审批时长、积压量；
- 护栏：动作质量不下降。

> 这个案例的价值不在“审批疲劳”本身，而在**数据来源校验**：很多“行为洞察”其实是埋点/测试数据的假象。

## 6. 怎么测：测试菜单

| 方法 | 什么时候用 | 单元 | 优点 | 缺点 |
| --- | --- | --- | --- | --- |
| **离线回放** | 早期筛选、不能花钱 | 历史 plan-day / account-day | 快、便宜、可复现 | 只能看相关，因果弱 |
| **影子模式** | 验证 Agent 判断、建立信任 | 账户/计划 | 不真实花钱 | 没有真实执行反馈 |
| **账户级 A/B** | 预算/出价策略 | 账户 | 因果强 | 样本要求高、竞价干扰 |
| **Switchback** | 时段/出价/节奏 | 账户-时间片 | 抗非平稳 | 设计复杂、可能泄漏 |
| **Stepped-wedge** | 产品功能逐步上线 | 组织/账户 | 实操可行 | 时间混杂 |
| **合成控制 / DiD** | 无法随机 | 账户/地区 | 可用观察数据 | 需要平行趋势假设 |
| **Holdout** | 长期效果/增量 | 账户/人群 | 看长期 | 收入损失、样本大 |

### 6.1 先算样本，再跑实验

- 连续指标（ROI）：若效应 0.2、标准差 0.8、α=0.05、power=0.8，每组约 **250** 个观测；计划级日数据可能够，账户级周数据通常不够。
- 比例指标（采纳率 25%→30%）：每组约 **1,200** 个样本。
- 样本不够时：先回放/影子，或者用贝叶斯/序贯方法，不要“跑一周就宣布显著”。

### 6.2 预注册

在跑之前写下来：

- 主指标、护栏、样本、时间窗；
- 分组方式、排除规则；
- 成功/失败阈值；
- 中途看几次（避免 peek 导致假阳性）。

### 6.3 读结果

- 效应大小 + 置信区间，不只看 p 值；
- 分群异质性：对谁有效、对谁无效；
- 护栏有没有破；
- 成本（消耗、算力、人工）；
- 机制是否被验证：如果效应出现了但机制不对，可能是别的原因。

## 7. 从假设到 Agent 能力

假设验证完，不要只写一份分析报告；要把它变成 Agent 的能力。

| 层 | 要定义 | 案例 A 的映射 |
| --- | --- | --- |
| **触发** | 什么条件下运行 | 学习期 + 3–14 天 + 转化 ≥20/天 |
| **输入/工具** | 需要哪些数据和工具 | `get_learning_state`、`get_budget_pacing`、`simulate_budget_change` |
| **策略** | 决策规则 + 幅度 + 阈值 | ROI <3.0 → 预算 -10%；ROI ≥3.5 → +5% |
| **输出** | 提案 + 证据 + 反事实 + 预期 | before/after、依据、如果不做会怎样 |
| **护栏** | 不能破的底线 | 预算 ±10%、库存 ≥7 天、余额 ≥3 天 |
| **评测** | 正例/反例/边界 | 低 ROI、高 ROI、转化不足、数据延迟、库存不足 |
| **遥测** | 记录什么 | 触发、动作、预测、实际、撤销、审批 |
| **版本** | 怎么迭代 | policy v1 → v2，A/B 对比 |

> **假设库 = 评测集**：每验证一个假设，就把它变成 3–5 个评测用例；每推翻一个假设，就把它变成反例。这样你的评测集不是拍脑袋写的，而是从真实策略里长出来的。

## 8. 常见坑（广告投放专属）

| 坑 | 表现 | 对策 |
| --- | --- | --- |
| **回归均值** | 低 ROI 计划本来就会反弹，被当成“干预有效” | 设对照；看多周期；用 DiD |
| **选择偏差** | Agent 只挑“看起来能救”的计划 | 意图治疗（ITT）分析；记录触发规则 |
| **竞价干扰** | 加预算影响竞争环境，对照组被污染 | 账户/地区分层；switchback |
| **非平稳** | 学习期、素材衰退、大促改变基线 | 时间固定效应；同期对照 |
| **归因/退款滞后** | 支付 ROI 好看，净成交 ROI 差 | 用净成交/退款口径；等结算窗口 |
| **数据延迟** | 日初数据不全，误判下滑 | 数据完整度门禁；连续窗口 |
| **幸存者偏差** | 只看还活着的计划，忽略被暂停的 | 保留全量；用历史快照 |
| **新奇效应** | 新素材/新策略短期涨，长期回落 | 观察 ≥7 天；看衰减曲线 |
| **指标作弊** | 砍消耗提 ROI，GMV 掉了 | 主指标 + 业务护栏（GMV/订单） |
| **多重比较** | 分了很多层，总有一层“显著” | 预注册；校正；只看主假设 |
| **人机混淆** | 审批/修改改变了处理组 | 记录谁改了什么；ITT + per-protocol |
| **模拟数据当真** | mock 没有因果信号，却得出“策略有效” | 明确边界；用回放/真实数据验证 |

## 9. 7 天产出计划

| 天 | 做什么 | 产出 |
| --- | --- | --- |
| D1 | 选 1 个决策（预算/暂停/出价）+ 1 个主指标 + 2 个护栏 | 一页“决策定义” |
| D2 | 用切片/趋势/异常找 10 个观察 | 观察清单（带数字） |
| D3 | 把 10 个观察收敛成 5 个洞察、3 个假设 | 3 张假设卡 |
| D4 | 给 3 个假设排优先级（影响 × 置信 × 成本） | 优先级表 |
| D5 | 给 Top 1 设计测试：对照、样本、时间窗、决策规则 | 实验设计一页 |
| D6 | 跑离线回放/影子；写 readout | 决策 memo（采纳/迭代/放弃） |
| D7 | 把结论变成 Agent 工具/技能 + 3 个评测用例 | 能力 spec + eval cases |

> 如果只有 3 天：D2 观察、D3 假设、D5 测试设计。先证明你会“想”，再证明你会“做”。

## 10. 面试怎么讲

### 10.1 1 分钟版本

> 我不会从“加个功能”开始，而是从一个决策开始：谁在什么场景下要做什么决定，错了代价多大。然后从数据里找异常、分层和反事实，提出一个带机制、带幅度、带时间窗的假设；再用最便宜的可信测试去验证；最后把验证过的策略变成 Agent 的工具、技能和评测用例。
>
> 比如学习期计划：我看到 18 个学习期计划 ROI 从 2.4 到 5.2，一刀切暂停会误伤高效计划。我的假设是“按 ROI 趋势 + 转化量 + 消耗规模分层干预”，对照是当前统一暂停；主指标 7 天 ROI，护栏是 GMV 和库存；先在历史数据上回放，再跑 2 周影子。如果 ROI +0.2、GMV 不低于 -5%，就把它做成 Agent 的学习期策略 skill，并配 5 个评测用例。

### 10.2 高频追问

- **“你怎么保证不是运气？”** 对照、时间窗、预注册、护栏；能回放就先回放。
- **“样本不够怎么办？”** 先影子/回放，别硬做 A/B；用分层/序贯/贝叶斯。
- **“如果结果和假设相反？”** 先检查机制、数据、执行；如果机制不成立，就放弃，并把它写成反例。
- **“你怎么知道 Agent 该不该做这个动作？”** 看动作质量（目标/方向/幅度/时机）、预测校准、护栏和撤销率，不只看 ROI。

### 10.3 不要说的话

- “我觉得加预算会更好。”——没有对照和机制。
- “跑了一周，ROI 涨了。”——没有基线、没有显著性、没有护栏。
- “用户说好用。”——行为指标比主观感受更可信。
- “数据支持这个结论。”——先问数据是谁产生的、样本多大、有没有偏差。
