# 技能 03：库存止损

> 商品库存快断时，计划还在花钱——继续投会带来退款、差评和履约压力；直接停又可能误伤。

---

## 1. 业务问题

高消耗计划 + 低库存，是商家最痛的风险组合：

- 继续投：卖出去发不了货，退款、差评、赔付；
- 直接停：可能只是短期库存波动，误伤一个正常计划；
- 优化师很难每天盯每个商品的库存。

这个技能的答案：

> **库存 ≤3 天，优先暂停；4–7 天，降预算 20%；库存充足或数据缺失，只观察。**

---

## 2. 绑定与工具

| 专家 | 做什么 |
| --- | --- |
| 数据分析 `analytics` | 查计划消耗、商品库存、可售天数，给证据 |
| 广告投放 `ads` | 提交暂停 / 降预算 20% 的待确认 Decision |

工具：`query_plans`、`get_account_plans`、`pause_plan`、`apply_budget_change`。

---

## 3. 步骤

1. 数据健康：库存数据是否可用；
2. 查计划消耗、状态、商品库存；
3. 算可售天数 = 库存 / 日均订单；
4. 库存 ≤3 天且计划投放中 → 暂停；
5. 库存 4–7 天 → 降预算 20%；
6. 库存充足 / 数据缺失 / 计划已暂停 → 只观察。

---

## 4. 输出

```json
{
  "verdict": "pause | reduce | observe",
  "evidence": ["库存 2 天；计划 7 天消耗 28,000", "..."],
  "action": "pause_plan 或 budget -20%",
  "guardrail": ["不向库存不足商品加预算", "动作可回滚"],
  "confidence": "low | medium | high"
}
```

---

## 5. 失败边界

- 库存数据缺失 → 只观察；
- 商品已下架 / 计划已暂停 → 只观察；
- 不向库存不足的商品加预算；
- 暂停/降预算都要人工确认，可回滚。

---

## 6. 评测用例

| case | 场景 | 期望 |
| --- | --- | --- |
| `is-001` | 库存 2 天 + 计划投放中 | 暂停 |
| `is-002` | 库存 5 天 + 计划投放中 | 降 20% |
| `is-003` | 库存 30 天 | 只观察 |
| `is-004` | 低库存但计划已暂停 | 只观察，不重复提交 |
| `is-005` | 库存数据缺失 | 只观察 |
| `is-006` | 库存 3 天，刚好到暂停线 | 暂停 |
| `is-007` | 库存 4 天，刚好进降预算区 | 降 20% |
| `is-008` | 库存 8 天 | 只观察 |
| `is-009` | 商品已下架 | 只观察 |
| `is-010` | 计划已结束 | 只观察 |

用例文件：[inventory-stop-loss.cases.json](inventory-stop-loss.cases.json)。

---

## 7. 为什么符合业务

- 库存是电商投放的真实约束，不是“为了用 AI 而用 AI”；
- 动作明确：暂停 / 降预算，都是优化师每天会做的动作；
- 有业务指标：库存天数、退款率、GMV、消耗；
- 有失败边界：数据缺失只观察，不硬下结论。
