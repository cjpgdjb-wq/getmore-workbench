# 技能 04：退款异常诊断

> 支付 ROI 好看，不等于赚钱。退款率一高，净成交和利润会被吃掉。

---

## 1. 为什么做

巨量千川已经支持「净成交出价」，商家也越来越关注净成交，而不是只看支付 GMV。  
但优化师日常仍容易只看支付 ROI，忽略：

- 退款率突然升高；
- 净成交金额下降；
- 支付 ROI 达标但利润变差。

这个技能的答案：

> **先看退款/净成交是否授权，再对比本周 vs 上周退款率；异常且消耗足够才降 10%，否则只观察。**

---

## 2. 怎么设计

```text
授权/数据健康
→ 本周 vs 上周退款率
→ 定位异常计划/商品
→ 净成交、支付 ROI、消耗
→ 退款率 >15% 或环比 +5pp，且消耗 ≥3,000
→ 降 10% / 只观察
```

关键边界：

- `partialAuth=true` → 只观察，不能拿输入里的 netRevenue 硬做判断；
- 计划已暂停 → 只观察；
- 消耗 <3,000 → 只观察；
- 单日尖刺 → 先观察，不直接降。

---

## 3. 业务关系

| 指标 | 技能怎么影响 |
| --- | --- |
| 退款率 | 超过 15% 或环比 +5pp 触发 |
| 净成交金额 | 判断退款对利润的真实影响 |
| 支付 ROI | 防止只看支付口径 |
| 回滚率 | 只降 10%，不暂停，可回滚 |

---

## 4. 评测

| case | 场景 | 期望 |
| --- | --- | --- |
| `rf-001` | 退款 18%，环比 +7pp，消耗够 | 降 10% |
| `rf-002` | 退款 22%，但净成交未授权 | 只观察 |
| `rf-003` | 退款 8% | 只观察 |
| `rf-004` | 退款 20%，但消耗 800 | 只观察 |
| `rf-005` | 退款 16%，但计划已暂停 | 只观察 |

skill 级真实 LLM：**5 / 5**。  
完整工具链：pass@3 3/3（降 10%，不暂停）。

---

## 5. 边界

- mock 数据，不是线上退款；
- 退款口径是 1 小时退款率，和 T+7 退款不同；
- 单日尖刺不直接降预算；
- 不暂停，只降 10%。

---

## 6. 为什么符合业务

退款异常是商家真实利润问题，不是平台指标游戏。  
这个技能把“支付 ROI 好看”拉回到“净成交和退款”，符合从支付口径走向经营口径的趋势。
