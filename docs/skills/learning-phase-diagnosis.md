# 技能 01：学习期诊断

> 第一个真正接到专家上的 skill：不是一段更长的 prompt，而是**触发 + 步骤 + 工具 + 输出 + 失败处理 + 评测用例**。
>
> 为什么做、和业务什么关系、面试怎么讲：见 [技能设计闭环](skill-design.md)。

---

## 1. 解决什么问题

优化师看到学习期计划 ROI 低于目标，常见的两个错误：

- **直接暂停**：打断学习，后面更难起量；
- **直接加预算**：学习期还没验证，越加越亏。

这个 skill 要给出第三种答案：

> **先确认是不是学习期、样本够不够、库存/余额是否支持；样本不足只观察，样本够才降预算 10%，不直接暂停。**

---

## 2. 绑定到谁

| 专家 | 用 skill 做什么 |
| --- | --- |
| 数据分析 `analytics` | 查数据、确认学习期、给证据，不提交动作 |
| 广告投放 `ads` | 基于证据提交「预算 -10%」或「只观察」的待确认 Decision |

---

## 3. 触发条件

- 计划处于学习期；
- ROI 低于计划目标；
- 用户问“要不要降预算 / 暂停 / 继续跑”。

---

## 4. 输入

```text
accountId, planId, learningDay, roi7d, roiGoal,
conversionsPerDay, costShare, stockDays, balanceDays,
dataLagMinutes, partialAuth
```

---

## 5. 步骤

1. 先看数据健康：延迟、授权、缺失字段；
2. 确认是否在学习期、第几天；
3. 对比 7 天 ROI / 订单成本与目标；
4. 检查消耗占比、库存可售天数、账户余额；
5. 样本不足（转化 <20/天）→ 只观察；
6. 样本够 → 降预算 10%，不直接暂停；
7. 库存/余额不足 → 只观察，不提交动作。

---

## 6. 输出

```json
{
  "verdict": "observe | reduce | pause",
  "evidence": ["3 条以内，必须带数字"],
  "action": "observe 或 budget -10%",
  "guardrail": ["GMV ≥ -5%", "库存 ≥7 天", "余额 ≥3 天"],
  "confidence": "low | medium | high"
}
```

---

## 7. 失败处理

- 数据延迟 / 缺失 → 只观察；
- 样本不足 → 只观察；
- 库存 <7 天或余额 <3 天 → 只观察；
- 不直接暂停学习期计划；
- 不写“已执行”，只提交待确认。

---

## 8. 评测用例

| case | 场景 | 期望 |
| --- | --- | --- |
| `lp-001` | 学习期第 5 天，ROI 2.8 / 目标 3.5，转化 30/天 | 预算 -10%，不暂停 |
| `lp-002` | 学习期第 2 天，转化 8/天 | 只观察，不提交动作 |
| `lp-003` | 学习期第 8 天，库存 2 天、余额 1 天 | 只观察，不加预算 |
| `lp-004` | 数据延迟 95 分钟 + 部分授权 | 只观察，不提交动作 |
| `lp-005` | 库存 3 天、余额 2 天 | 只观察，不降预算 |
| `lp-006` | 转化 19/天，刚好低于样本门槛 | 只观察 |
| `lp-007` | 转化 20/天，刚好达到样本门槛 | 降 10% |
| `lp-008` | 库存 7 天、余额 3 天 | 降 10% |
| `lp-009` | 数据延迟 60 分钟 | 只观察 |
| `lp-010` | 计划已暂停 | 只观察，不重复提交 |

用例文件：[learning-phase-diagnosis.cases.json](learning-phase-diagnosis.cases.json)。
