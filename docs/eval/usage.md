# 策略实验使用数据

> 一句话：**先看优化师有没有真的打开、开始、回滚，而不是只看推荐准不准。**

---

## 1. 记录什么

| 事件 | 什么时候记 |
| --- | --- |
| `view` | 打开策略实验抽屉 |
| `start_action` | 开始一个“带动作”的实验 |
| `start_observe` | 开始一个“只观察”的实验 |
| `dismiss` | 对推荐点“不感兴趣” |
| `readout` | 进行中实验做复盘 |
| `rollback` | 回滚实验动作 |
| `cancel` | 取消未确认的实验 |

本地文件：`.runtime/partner/experiment-events.json`。

---

## 2. 看什么

抽屉顶部一行：

```text
本地累计：打开 12 · 开始 3 · 回滚 1
平均每次打开开始 0.3 个 · 回滚率 33%
```

三个数就够：

- **打开 → 开始**：推荐有没有让人想试；
- **开始 → 回滚**：实验动作是不是经常要退；
- **打开 → 不感兴趣**：推荐是不是不相关。

抽屉里还会直接给一句诊断：

```text
打开多、开始少：先看推荐依据是否可信。
回滚偏多（1/2 次）：先收紧动作幅度或护栏。
样本还少（打开 2 次），再积累几次再判断。
```

---

## 3. 怎么读

- 打开多、开始少：推荐不够具体，或优化师不信任；
- 开始多、回滚多：动作太激进，或护栏太松；
- 打开少：入口不明显，或优化师不需要这个功能；
- 不感兴趣多：推荐模板不对。

---

## 4. 边界

- 这是**本地演示事件**，不是生产埋点；
- 没有用户 ID、会话 ID，不能算真实留存；
- 一次打开可能看到 3 张卡，不能把“开始/打开”直接当转化率；
- 生产要补：用户/账户维度、曝光位置、停留时长、确认率、7 天留存。

---

## 5. 下一步

1. 先看一周的打开/开始/回滚；
2. 如果“打开多、开始少”，先改推荐文案和依据；
3. 如果“开始多、回滚多”，先改动作幅度和护栏；
4. 再接真实埋点，不急着做复杂看板。
