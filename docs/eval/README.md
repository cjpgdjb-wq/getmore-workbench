# 策略实验评测：历史回放 v0.4

> 目标：把“策略实验”从“看起来合理”变成“有事后标签、有对照、可回归”。

> 工作台入口：策略实验抽屉底部「评测记录」→ 三行版本对比。

---

## 1. 做什么

```text
选 60 个历史 T0
→ 只给推荐引擎 T0 前的数据
→ 推荐引擎给出动作
→ 用 T+7 的真实 mock 数据做“事后标签”
→ 与 T0 时相似的计划/账户做对照
→ 算方向准确率、安全准确率、校准、护栏
```

这不是严格因果 A/B，而是**历史回放 + 事后相对表现**。

---

## 2. 怎么跑

```bash
node scripts/eval-strategy.mjs   # v0.2 默认规则：生成 60 个 case + 报告
node scripts/eval-policy.mjs     # 固定 case：v0.2 vs v0.3 vs v0.4
```

输出：

```text
docs/eval/cases.json           # 60 个 case（含 visible / hidden）
docs/eval/report.md            # v0.2 人读报告
docs/eval/report.json          # v0.2 机读指标
docs/eval/policy-v0.4.md       # v0.2/v0.3/v0.4 固定 case 对比
docs/eval/v0.1/                # 第一版 30 case 存档
docs/eval/v0.2/                # v0.2 60 case 存档
```

## 3. 当前结果

> 2026-11-08 数据修订（净成交/退款口径 + 素材数据）后，固定 case 复跑：v0.3 66.7%、v0.4 71.7%；正文的 68.3%/80.0% 是修订前快照。`qa:eval` 动态生成 case 复跑为 55.0%，与固定 case 不一致，说明 case 尚未冻结。

### v0.2 默认规则（60 case）

- 方向准确率：**61.7%**（95% CI 50.0%–73.3%）；
- 安全准确率：**53.3%**；
- 永远只观察 baseline：**63.3%** —— 规则没有跑赢 baseline；
- 31 个动作里 16 个通过 GMV 护栏；
- 校准 MAE：0.28；
- 分模板：学习期 100%、低 ROI 66.7%、高 ROI 10.0%、预算撞线 12.5%。

结论：**降预算类规则有效；加预算类规则在 T+7 上不成立，是主要错误来源。**

### v0.3 固定 case 保守策略

固定 v0.2 的 60 个 case，只改策略：关闭“预算撞线 / 高 ROI 低消耗”的加预算建议。

| 策略 | 方向准确率 | 安全准确率 | 动作数 | 护栏通过 |
| --- | --- | --- | --- | --- |
| v0.2 默认 | 61.7% | 53.3% | 31 | 16 |
| **v0.3 保守** | **68.3%** | **60.0%** | 13 | 8 |
| baseline 只观察 | 63.3% | -- | 0 | -- |

分模板：学习期 100%、低 ROI 66.7%、高 ROI 60%、预算撞线 0%。

结论：

- 保守策略跑赢 baseline 约 5pp；
- 但预算撞线模板降到 0%：这些 case 的事后标签是“降预算”，只关闭加预算不够；
- 下一版给预算撞线单独做“降预算”规则。

### v0.4 固定 case 防守策略

固定同样的 60 个 case：

- 关闭高 ROI 加预算；
- 预算撞线改为“降预算 10%”，不再只观察。

| 策略 | 方向准确率 | 安全准确率 | 动作数 | 护栏通过 |
| --- | --- | --- | --- | --- |
| v0.2 默认 | 61.7% | 53.3% | 31 | 16 |
| v0.3 保守 | 68.3% | 60.0% | 13 | 8 |
| **v0.4 防守** | **80.0%** | **60.0%** | 21 | 9 |
| baseline 只观察 | 63.3% | -- | 0 | -- |

分模板：预算撞线方向 **87.5%**，但安全准确率 **0%**；降预算方向对，GMV 护栏会破。

结论：**方向准确率提升来自“预算撞线从加预算改成降预算”，但保 ROI 和保 GMV 仍在冲突。** 下一版要比较 -5% / -10% / 暂停三种幅度。

## 5. 标签怎么来

- 方向标签：看 T+7 的 DiD（相对对照的 ROI 变化）+ 相对 GMV；
- 样本不足（转化 <20/天 或 消耗 <3,000/7d）→ 标签为“只观察”；
- 对照：同投放方式/同目标、T0 时 ROI/消耗最接近的计划/账户；
- 护栏：相对对照的 GMV 变化 ≥ -5%；
- 学习期：按 `learningStartedAt` 还原，不用当前状态。

---

## 6. 边界

- **不是因果 A/B**：对照是匹配出来的，不是随机分组；
- **不是真实平台数据**：mock 数据只验证方法；
- **不是唯一评测**：还要评 LLM 输出、工具调用、解释质量；
- **一个 case 只是一个样本**：要 30–100 个 case 看分布。

---

## 7. 下一步

1. 给“预算撞线”比较 -5% / -10% / 暂停三种降幅，选安全准确率最高的；
2. 固定 60 个 case，做 v0.5，避免样本漂移；
3. 接 LLM Agent，比较“规则 vs Agent”的方向准确率与护栏通过率；
4. 在策略实验 UI 里标出“只观察”的原因；
5. 把 `qa:eval` + `qa:policy` 接进回归，每次改规则自动跑。
