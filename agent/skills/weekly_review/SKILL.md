# 周报复盘

把一周的账户/计划变化整理成可贴群的周报，不提交动作。

## 什么时候用

- 写周报
- 本周复盘
- 汇报本周投放

## 业务问题

优化师每周都要写复盘：拉数、对比、找变化、写下周动作；重复劳动，而且容易漏掉数据缺口。

## 方法

固定结构：本周总览 → 本周 vs 上周 → 3 个关键变化 → 2 个下周动作 → 数据缺口。只读，不提交 Decision；缺数据显式说明。

## 步骤

1. 拉本周账户/计划汇总
2. 对比本周 vs 上周
3. 找 3 个关键变化
4. 给 2 个下周动作
5. 显式写数据缺口

## 输出

```json
{
  "verdict": "report",
  "report": "Markdown 周报",
  "evidence": [
    "3 条以内，必须带数字"
  ],
  "guardrail": [
    "只读，不提交动作",
    "缺数据显式说明"
  ],
  "confidence": "low | medium | high"
}
```

## 护栏

- 只读，不提交动作
- 缺数据显式说明

## 失败处理

数据缺失/延迟时，在周报里写明，不推断缺失为 0。

## 使用边界

- 技能只提供方法与判断顺序，不直接执行动作；动作由工具提交，写操作必须人工确认。
- 没有工具返回的数字，不要编造；缺数据时按失败处理执行。
